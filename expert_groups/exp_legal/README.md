# exp_legal — legal expert group

Expert group that trains on
[joelniklaus/Multi_Legal_Pile](https://huggingface.co/datasets/joelniklaus/Multi_Legal_Pile)
(multilingual `all_all` — all 33 shards across every language and
document-type subset) at 50/50 weight against
[allenai/c4](https://huggingface.co/datasets/allenai/c4) for general-text
grounding.

Multilingual `all_all` was chosen over English-only `en_all` after analysis
showed the English subset totals only ~36 k rows — small enough for a
single miner to memorize inside a day of continuous training and collapse
ranking quality. The multilingual mix is ~500 MB compressed across
33 shards, providing a much larger eval pool and encouraging miners to
learn cross-jurisdictional legal patterns rather than overfit to one
corpus.

**Chain `group_id`: `3`** (parallel to `exp_math=0`, `exp_dummy=1`,
`exp_c4_p02=2` — the frozen natural-routing helper slot, which loads
alongside exp_legal via `TaskCfg.helper_group_id=2`).

Plan and rationale: [docs/exp-legal-migration-plan.md](../../docs/exp-legal-migration-plan.md).

## `expert_assignment.json`

Generated by streaming 50 batches of `joelniklaus/Multi_Legal_Pile`
through DeepSeek-V2-Lite in inference mode and recording which routed experts
the MoE gate actually selects on legal text. 26 layers × 8 experts per layer,
selection metric = summed router weight. (First generated against `en_all`;
should be regenerated against `all_all` before the network activation to
reflect multilingual routing patterns.)

To regenerate (if the dataset mix or base model changes):

```bash
python expert_groups/build_expert_assignment.py \
  --task exp_legal \
  --output expert_groups/exp_legal/expert_assignment.json \
  --num-batches 50 \
  --experts-per-layer 8
```

Runtime: ~30 min on an A100. Inspect the resulting per-layer expert
distribution before committing — if a layer collapses to <3 distinct experts,
re-run with `--num-batches 100`.

## ⚠️ Pre-launch follow-up: `eval_source_seeded_shard_pick: false` in `config.yaml`

Set to `false` to disable the validator-consensus seeded shard-pick path, which requires
each HF source to be registered in
`connito/shared/eval_shard_pick.py:_KNOWN_SOURCES`. MultiLegalPile isn't
registered yet.

To flip back to `true`:

1. Add `(joelniklaus/Multi_Legal_Pile, all_all)` to `_KNOWN_SOURCES` with
   a `_SourceShardPolicy` entry:
   - `row_count_source="constant"` (MultiLegalPile is `.jsonl.xz`, no
     parquet footer)
   - `verified_shard_rows` populated by an offline script that streams
     every shard and counts lines (~2-4 hours of wall time across all
     33 shards)
   - `safe_floor_rows` = smallest verified shard count
   - `min_headroom_rows` = 5000
   - Note: `_SHARD_NAME_FILTER` in `eval_shard_pick.py` currently
     matches `(train|part_)`; MultiLegalPile's filenames follow the
     `<language>/<doctype>/<source>.jsonl.xz` pattern instead, so
     either add a per-source pattern to `_SourceShardPolicy` or extend
     the regex before registering.
2. Pin a known-good HF revision SHA (e.g., `911e1d214162fd11d2c78d3f1428cbfcbe07782c`
   is the current head as of 2026-07-03)
3. Add a unit test that imports `eval_shard_pick` and asserts
   `pick_shard_for_source("joelniklaus/Multi_Legal_Pile", "all_all", ...)`
   returns a valid pick.
4. Flip this config field to `true` (or remove the line; `true` is the
   default).

Until then, validators on `exp_legal` use the legacy head-of-stream eval
path. Consensus determinism across validators is weaker than the
seeded-pick guarantee `exp_math` enjoys.
